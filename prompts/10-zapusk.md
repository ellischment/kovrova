# Фаза 10: Запуск (QA, параллельная работа, переключение с DIKIDI)

> Запуск: `/phase 10`. Оркестратор: Opus. Исполнители: `qa-engineer`, `critic-5`, `backend-builder`, `bot-builder`.
> Ворота: **G7**: решение о переключении.

## Задачи
1. **Регресс:** все сценарии ТЗ §19 на staging, мобайл и десктоп; Lighthouse и axe на всех типах страниц; нагрузка открытия месяца (200 пользователей).
2. **Финальное ревью** `/review-5` по всему продукту → топ-3 внести.
3. **Мониторинг:** алерты в админ-бот (вебхук оплаты, outbox, 5xx, бэкап); health-check; уведомление, если `release:open` не отработал.
4. **Миграция будущих броней из DIKIDI** (ТЗ §18): скрипт импорта из CSV (минимум полей), статус CONFIRMED, source=`dikidi_import`, без рассылок; сверка с Ириной.
5. **Параллельная работа 2–4 недели:** сайт в режиме `native`, DIKIDI открыт только на ближайшие даты; в DIKIDI — описание «записывайтесь на сайте <домен>». Еженедельный отчёт в `docs/progress/launch-week-N.md`: записи по каналам, конверсия виджета, выкупы из листа, жалобы.
6. **Переключение (после G7):** закрыть онлайн-запись в DIKIDI, оставить профиль витриной; обновить ссылки в Telegram-канале, Картах, 2ГИС, закрепе; сообщение гостям в голосе Ирины (шаблон — copywriter, утверждает Ирина).
7. **Ретроспектива:** метрики «до / после» по ТЗ §1.2; список улучшений v2 → `docs/progress/v2-backlog.md`.

## Критерии приёмки
- 0 BLOCKER/MAJOR в последнем цикле ревью.
- 2 недели параллельной работы без потерянных броней и без двойных записей.
- G7 принят, ссылки везде обновлены, откат (`BOOKING_MODE=dikidi`) проверен.
