# Фаза 04: Движок записи (backend)

> Запуск: `/phase 04`. Оркестратор: **Opus**. Исполнители: `architect` (уточнение ADR), `backend-builder`, `qa-engineer`.
> Ворота: **G4** (налоговый статус и эквайринг). Без G4 делаем всё, кроме реального провайдера: платёжный адаптер с фейковым провайдером.

## Прочитать
`docs/02-TZ.md` §6, §7, §16.3–§16.5, §17, §19 (сценарии 1, 3, 4, 6); ADR 0002, 0003; `packages/contracts`.

## Задачи
1. **Расчёт слотов** (чистый модуль `backend/src/booking/slots.ts`): шаблон недели, якоря или сетка, исключения, буферы, минимальный срок, окно записи (MONTHLY_RELEASE / ROLLING + ранний доступ), доступность по матрице цен. **Сначала тесты:** таблица кейсов (пересечения, граница дня, отпуск, смена летнего времени не нужна — МСК без DST, но тест на «24:00», пустой шаблон, якорь, в который не помещается длительность).
2. **Бронь:** `POST /api/public/bookings` → HOLD (10 мин, из Setting) → `payUrl` или CONFIRMED (если предоплата выключена). Ограничение исключения + перехват конфликта → 409 + 3 ближайшие альтернативы. `Idempotency-Key`. Короткий код и `manageToken` (в БД хэш).
3. **Клиент и согласия:** поиск или создание по телефону (E.164); запись `Consent` (тип, версия документа, sha256 текста, IP, UA, источник). Без согласия PD — 422.
4. **Первичный приём:** доступен только для телефона без визитов (иначе 409 с подсказкой).
5. **Управление записью** `/api/public/manage/:token`: просмотр, отмена (расчёт возврата по правилам §7.4), перенос (проверка правил и слотов, атомарно), смена техники (до дедлайна), «записаться снова» (предзаполнение).
6. **Платежи:** интерфейс `PaymentProvider` (createPayment, refund, verifyWebhook) + `FakeProvider` для тестов и staging. Вебхук: подпись, идемпотентность, переход PENDING_PAYMENT → CONFIRMED, запись `Payment`. Реальный провайдер — после G4 (ЮKassa / Robokassa / Т-Банк — по ADR `0007-ekvajring.md`, агент `architect` сравнивает актуальные условия: СБП, возвраты, чеки НПД или 54-ФЗ).
7. **Фоновые задачи** (`jobs.ts` + `job-schedules.json`): `booking:holds:expire`, `bookings:autocomplete`; событие `SlotFreed` публикуется в outbox (для фазы 06).
8. **Кэш слотов** 30–60 с с инвалидацией на изменения.
9. **Каталог** `GET /api/public/catalog` и **слоты** `GET /api/public/slots` (+ `nearest`).
10. **Нагрузка:** тест 20 параллельных броней на слот (ровно 1 HOLD); 200 одновременных запросов слотов — p95 < 500 мс локально.

## Критерии приёмки
- Покрытие `slots`, `cancellation-rules`, `booking-state` ≥ 90%.
- Тест конкурентности зелёный.
- OpenAPI обновлён; контракты совпадают с ответами (тест схем).
- Логи без ПДн (тест: телефон в логах маскирован).
- `compliance-reviewer` PASS.
