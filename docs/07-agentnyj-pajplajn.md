# 07. Агентный пайплайн: как это строится без ваших рук на каждом шаге

> Коротко: **да, эту задачу лучше делать агентами**, но не одним «сделай сайт», а конвейером с ролями, контрольными точками и памятью между сессиями.
> Вы участвуете только в **7 человеческих воротах** (решения, которые может принять только Ирина или вы). Всё остальное агенты делают циклами сами.

---

## 1. Схема

```
                    ┌──────────────────────────────────────────────┐
                    │  ОРКЕСТРАТОР (основная сессия Claude Code)   │
                    │  читает STATUS.md → выбирает задачу фазы →   │
                    │  планирует → раздаёт → принимает → коммитит  │
                    └───────┬───────────────┬───────────────┬──────┘
            разведка        │   сборка      │   проверка    │  ревью
        ┌───────────┐  ┌────▼─────┐  ┌──────▼─────┐  ┌──────▼────────────┐
        │  scout    │  │ builders │  │ qa-engineer│  │ compliance-reviewer│
        │ (дёшево)  │  │ frontend │  │ тесты, e2e,│  │ critic-5 (5 точек  │
        │ карта кода│  │ backend  │  │ Lighthouse,│  │ зрения)            │
        └───────────┘  │ bot      │  │ axe        │  └────────────────────┘
                       │ designer │  └────────────┘
                       │ copywriter│
                       │ seo      │
                       │ architect│
                       └──────────┘
   Память между сессиями: docs/progress/STATUS.md · docs/HUMAN-TODO.md · docs/adr/*.md · git history
```

## 2. Роли и модели (экономия токенов)

| Агент (`.claude/agents/`) | Модель | Права | Задача |
|---|---|---|---|
| `scout` | **haiku / sonnet** | только чтение | Первичная разведка: карта файлов, связей, тестов (≤ 500 слов). Идея [code-scout](https://github.com/di-sukharev/code-scout-skill): дорогая модель не тратит токены на поиск |
| `architect` | **opus** | docs/adr, contracts | ADR, модель данных, контракты API, выбор провайдеров |
| `designer` | sonnet | website (стили), assets | Токены, компоненты, SVG haikei, макеты |
| `frontend-builder` | sonnet | website, webapp | Astro-страницы, виджет записи, админка |
| `backend-builder` | sonnet | backend, contracts | API, Prisma, слоты, брони, платежи, jobs |
| `bot-builder` | sonnet | backend/notifications | Outbox, Telegram, MAX, SMS, email, шаблоны, лист ожидания |
| `copywriter` | sonnet | content/, тексты | Тексты голосом Ирины по словарю «не медицина» |
| `seo-specialist` | sonnet | website (meta, schema) | Мета, JSON-LD, sitemap, llms.txt, перелинковка |
| `qa-engineer` | sonnet | запуск команд, tests/ | Unit, Playwright (мобайл), Lighthouse, axe, сетевой аудит «нет Google» |
| `compliance-reviewer` | **opus** | только чтение | 152-ФЗ, реклама, «не медицина», запрет попапов. Вердикт BLOCKER/MAJOR/MINOR |
| `critic-5` | **opus** | только чтение | Ревью UX с 5 точек зрения (практик, скептик, экономист, историк, академик) |

**Правила экономии:**
1. Оркестратор не читает большие файлы сам: сначала запрашивает у `scout` карту.
2. Бриф исполнителю — конкретный: файлы, критерии приёмки, чего не трогать. ТЗ целиком не пересылается, только нужные разделы (`docs/02-TZ.md#7-движок-записи`).
3. Ревьюеры получают **только diff фазы** и чек-лист, не весь репозиторий.
4. Цикл исправлений — не больше 3 итераций на задачу. Если не сходится, задача уходит в `HUMAN-TODO.md` с конкретикой, а не «пытаемся ещё».
5. Независимые задачи (frontend и backend по готовому контракту) — параллельно, в отдельных worktree.
6. Для рутинных фаз оркестратор можно запускать на Sonnet, Opus — для фаз 01 (архитектура), 04 (движок) и 06 (лист ожидания) и для финальных ревью.

## 3. Цикл одной задачи

```
1. SCOUT      scout → карта (что есть, где, какие тесты)
2. PLAN       оркестратор → TaskCreate: подзадачи + критерии приёмки из ТЗ §19
3. BUILD      builder(ы) → код + тесты (тесты пишутся ДО/ВМЕСТЕ, не после)
4. VERIFY     qa-engineer → typecheck, lint, unit, e2e (мобайл), Lighthouse/axe при UI
5. REVIEW     compliance-reviewer (+ critic-5 для UX) по diff — параллельно
6. FIX        builder исправляет BLOCKER/MAJOR → снова 4–5 (≤ 3 итераций)
7. GATE       /done-check: все критерии зелёные, нет BLOCKER, документация обновлена
8. COMMIT     conventional commit → push → (PR)
9. REMEMBER   STATUS.md: сделано / дальше / блокеры; HUMAN-TODO.md: вопросы людям
```

## 5. Как запускать

### Вариант А — по фазам (рекомендуется на старте)
В новой сессии Claude Code в этом репозитории:
```
/phase 00
```
Навык `phase` сам прочитает `prompts/00-*.md`, STATUS и выполнит цикл. После фазы:
```
/phase 01
```
и так далее. Между фазами можно делать `/clear`: вся память лежит в файлах.

### Вариант Б — автопилот
Промпт `prompts/99-autopilot.md` в режиме `/loop` (без интервала, агент сам выбирает темп) или как Routine (плановый запуск раз в N часов). Каждый запуск берёт следующую незаблокированную задачу, проходит цикл и останавливается на человеческих воротах. Оповещение приходит в приложение.

### Вариант В — параллельные сессии
Для фаз 04–07 после готовых контрактов: одна сессия — backend, другая — frontend, третья — боты. Каждая в своей ветке, слияние через PR.

## 7. Что делает Manus, а что нет
Manus (manus.im) — автономный агент с браузером. Используем его **только для внешнего исследования**: конкуренты в Видном, Мисайлово и Домодедово, их цены и форматы, выдача и Карты по ядру запросов, референсы сайтов практиков. Промпт — `prompts/manus-research.md`. **Никаких данных гостей в Manus** (зарубежный сервис → трансграничная передача).

## 8. Риски процесса и защита
| Риск | Защита |
|---|---|
| Агент «додумал» факт (цену, адрес) | Все факты берутся только из `docs/08` и `content/`; неизвестное → `[?]` и HUMAN-TODO |
| Дрейф стиля или тона | copywriter + compliance-reviewer на каждом PR с текстами |
| Сломанный прод | staging в Yandex Cloud, e2e перед деплоем, откат через предыдущий образ |
| Разрастание контекста | scout-карты, брифы, `/clear` между фазами, STATUS ≤ 150 строк |
| Зацикливание | ≤ 3 итераций исправлений, затем эскалация человеку |
