# 05. Право: 152-ФЗ (редакция 2025–2026), реклама, «не медицина»

> ⚠️ Это технический чек-лист для разработки, **не юридическая консультация**. Финальные тексты документов и уведомление в РКН проверяет юрист (фаза 09). Нормы и суммы штрафов перепроверяются на дату запуска.

## 2. Какие данные собираем и зачем (минимизация)

| Данные | Цель | Основание | Срок хранения [? юрист] |
|---|---|---|---|
| Имя | обращение, запись | согласие | пока есть активные отношения + 3 года после последнего визита, затем обезличивание |
| Телефон | запись, уведомления, идентификация | согласие | то же |
| Email (необязательно) | чеки, сертификаты | согласие | то же |
| Telegram/MAX chat_id | уведомления | согласие (гость сам подключает) | до отключения или отзыва |
| Комментарий к записи | пожелания к сеансу | согласие | 1 год |
| История записей и платежей | исполнение услуги, учёт | договор, налоговый учёт | по налоговым срокам |
| IP, user-agent в журнале согласий | доказательство согласия | законный интерес оператора | весь срок + 3 года |
| **Сведения о здоровье** | **НЕ собираем онлайн** | — | — |

**Здоровье — специальная категория (ст. 10).** Для её обработки нужно письменное согласие. Поэтому:
- в форме записи поле «комментарий» с подсказкой не писать о здоровье; если введены явные медицинские слова — мягкое предупреждение (не блокировка);
- анкета первичного приёма заполняется **на бумаге в кабинете** вместе с письменным согласием; хранится в запираемом шкафу; в систему не вносится;
- админ-заметки о госте — с подсказкой «без сведений о здоровье».

## 3. Документы (генерирует агент, проверяет юрист)

| Документ | URL | Ключевое |
|---|---|---|
| Политика обработки ПДн | `/legal/politika` | оператор (ФИО, ИНН, адрес), цели, перечни, сроки, права субъекта, порядок запросов (ответ в течение 10 рабочих дней), меры защиты, трансграничная передача, дата и версия |
| **Согласие на обработку ПДн** | `/legal/soglasie` | отдельный документ: перечень ПДн, цели, действия, способы, третьи лица (эквайринг, SMS-провайдер, мессенджеры, хостинг), срок, порядок отзыва |
| Согласие на рекламные сообщения | `/legal/soglasie-reklama` | отдельная галочка, по умолчанию выключена |
| Согласие на распространение (отзывы) | `/legal/soglasie-rasprostranenie` | форма с требованиями ст. 10.1: что именно публикуем (имя, текст, услуга), где, условия и запреты |
| Правила записи и отмены (оферта) | `/legal/pravila-zapisi` | предоплата, отмена и перенос, возвраты, неявка, смена техники, сертификаты, абонементы, претензии; «услуги не являются медицинскими» |
| Политика cookie | `/legal/cookies` | какие cookie, зачем, как отключить |
| Реквизиты | футер | ФИО, статус (ИП / НПД), ИНН, ОГРНИП (если ИП), контакт для обращений по ПДн |

Каждый документ имеет версию. В журнале согласий хранится `docVersion` и `sha256(text)`. При изменении текста новые согласия идут по новой версии, старые остаются доказательством.

## 4. Технические требования (проверяются e2e и агентами)

- [ ] Галочка согласия **не отмечена** по умолчанию; без неё кнопка неактивна; рядом ссылка на полный текст.
- [ ] Галочка рекламы — отдельная, необязательная, не отмечена.
- [ ] Журнал `Consent`: тип, версия, хэш, время, IP, UA, источник (сайт / бот / админ).
- [ ] Отзыв согласия: ссылка в каждом сообщении («отписаться»), кнопка в боте, email для запросов; обработка ≤ 10 рабочих дней, автоматическая для рекламы (немедленно).
- [ ] «Скачать мои данные» и «удалить мои данные» — через ссылку управления записью (с подтверждением по SMS/мессенджеру).
- [ ] **Ни одного запроса к Google, Meta и прочим зарубежным трекерам** (e2e проверяет сетевой лог). Шрифты — self-host. Капча — Yandex SmartCaptcha.
- [ ] Яндекс Метрика грузится **только после согласия** в немодальной полосе; Вебвизор выключен (не записываем ввод в формы). Umami — без cookie и без хранения IP.
- [ ] Все хранилища с ПДн (PostgreSQL, бэкапы, логи, Object Storage) — в РФ (Yandex Cloud, `ru-central1`).
- [ ] Логи не содержат ПДн: телефоны маскируются (`+7 916 ***-**-58`), комментарии не логируются.
- [ ] Бэкапы шифруются, доступ по ролям, восстановление проверено.
- [ ] Админам — 2FA; аудит-лог действий с ПДн; ассистент не может выгружать базу.
- [ ] Сообщения в мессенджерах — минимум данных (без комментариев и без упоминания характера услуги, если гость выбрал «скрывать название услуги» [опция]).
- [ ] Платёжные данные карт не касаются наших серверов (платёжная страница провайдера).
- [ ] План реагирования на инцидент: `docs/runbooks/incident.md` (кто, что, 24/72 ч).

## 5. Трансграничная передача: Telegram
Отправка напоминаний через Telegram-бота может рассматриваться как трансграничная передача ПДн (сервера за рубежом). Варианты для юриста:
1. Указать в уведомлении РКН и в согласии; минимизировать данные в сообщениях.
2. Давать гостю выбор канала: MAX или SMS как равноценная альтернатива.
3. Telegram — только по явному выбору гостя (он сам нажимает `/start`).

## 6. Реклама и формулировки
- Закон «О рекламе»: не выдавать услуги за медицинские, не обещать излечение; отзывы — только реальные и с согласием.
- Рекламные рассылки — только с отдельным согласием (ст. 18 38-ФЗ).
- Платные посты с продвижением сайта в чужих каналах — **маркировка (erid)** через ОРД.
- Словарь «не медицина» — в `03-dizajn-sistema.md`, раздел 7.2. Compliance-агент блокирует PR с запрещёнными словами в пользовательских текстах.

## 7. Налоги и чеки (закрыть до выбора эквайринга)
- НПД (самозанятость): чеки через «Мой налог» (провайдер умеет формировать автоматически); **лимит дохода 2,4 млн ₽/год** — проверить актуальность и сравнить с выручкой.
- ИП: онлайн-касса по 54-ФЗ (облачная касса у провайдера эквайринга).
- Предоплата, возвраты и сертификаты — корректные типы чеков (аванс, зачёт аванса).

## 8. Перенос данных из DIKIDI
- Массово гостей для рассылок не переносим.
- Будущие брони переносим с минимумом полей (имя, телефон, время) для исполнения услуги; при первом взаимодействии в новой системе гость подтверждает новые согласия.
- Отзывы из DIKIDI не копируем без согласия авторов — ставим ссылку на профиль.
